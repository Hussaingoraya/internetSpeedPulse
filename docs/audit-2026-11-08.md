# Website audit — November 8, 2026

Scope: existing InternetSpeed Pulse on Hostinger Business, repository `Hussaingoraya/internetSpeedPulse`. Preserve the identity and existing six guides; no new overlapping articles or invented field tests.

## Measurement findings and changes

- Live deployment returned 200 for homepage, sitemap, robots, ads.txt and connection API. Hostinger returned null provider metadata; no ISP lookup or fabricated Etisalat label was added.
- Existing preflight checks already requested real binary data and sent an upload. LibreSpeed used progress bytes, not fabricated rates. The integration keeps decimal Mbps and a 1.0 overhead factor. Default derivative settings now also use 1.0.
- Added individual 15-second XHR deadlines, request-specific Resource Timing lookup, strict download byte/type checks, response-level upload errors and at least one successful upload acknowledgement before a completed upload can be reported. Existing 75-second overall cancellation and short control-probe deadlines remain.
- Maximum download request is 8,000,000 bytes; upload body is 4 MiB. Each direction reserves at most 512,000,000 bytes, including warm-up. When the next request would exceed it, the run is incomplete and cannot be saved/exported. Very fast links can hit this safeguard; no truncated result is represented as a full sustained test.
- First-party downloads use fresh random data in each 64 KiB block, avoiding a repeated pattern that a proxy might compress. Cache-Control includes no-store and no-transform. Upload bodies are streamed, size-checked even without Content-Length, and bounded by a 15-second read deadline and request abort signal.
- A runtime per-process payload budget defaults to 10 GB/hour. Reservations are conservative and not refunded for cancellation. It is configurable with MEASUREMENT_HOURLY_BYTES. MEASUREMENT_ENABLED=false disables first-party transfers. These controls are not a distributed billing cap: restarts and multiple processes have separate counters. Hostinger/WAF quotas are still necessary for abuse and monthly cost protection.
- The data warning appears before Start. Hiding the tab stops the run. Screen readers announce phase changes and the completed summary instead of every rate update. Missing metrics show an em dash. Partial/error results remain unexportable.
